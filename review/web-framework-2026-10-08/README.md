## First package: toolchain and desktop route shell

Final checks use Node 22.23.3 / npm 10.9.9, Next 16.4.0, React 19.3.0, TypeScript 6.0.3 and Biome 2.5.15. Recorded logs: production build, type generation/typecheck, lint, six locale/path unit cases, and three headed desktop Chrome journeys. The latter cover locale-preserving deep links, refresh, skip-link keyboard focus, an automated accessibility check, no-JavaScript reading, 404s for unavailable/private routes and absent source-file delivery. Browser checks use a fresh context at 1440 × 900. They are limited foundation checks, not complete WCAG/security/production acceptance.

The first browser run found an unlandmarked preview notice and HTTP 200 from streamed not-found routes. The notice is now inside the header; the loading boundary now applies only to the public route group. The subsequent browser suite passed without weakening either assertion. The first sandbox build could not bind an internal Turbopack worker port; the authorized unsandboxed local build passed. No external error report was sent. A later visual pass found a missing browser-tab icon; a local SVG icon and favicon redirect remove the console 404. The final three browser journeys include a console-error assertion.

ESLint 10 had two plugin peer conflicts, and the compatible ESLint 9 line is end-of-life. Biome replaces that development stack. Final `audit-all.json` and `audit-production.json` report zero findings; the earlier braces development advisory is no longer in the resolved dependency tree. Audits are point-in-time checks, not a security warranty. `npm ls --all` also passes with no invalid peers.

The [desktop capture](shell-desktop/summary.json) records five screenshots: VI/EN home, English about, 1280 × 800 VI home, and 200% CSS text resizing with keyboard focus. The primary agent visually inspected all five: navigation and text remain readable, with no horizontal overflow. At 200% text size, the focused skip link temporarily overlays part of the brand; its focus and destination remain visible. This is text resizing, not browser zoom. The final 50 requests were local with no console/page/request errors. Axe reported zero violations and 19 passes per home language, but color contrast was incomplete; this is not a full accessibility pass. All 24 source/configuration hashes match before/after the capture. A separate [contrast calculation](shell-desktop/contrast-supplement/contrast-calculations.json), reviewed by the primary agent, converts those exact CSS colors through Chrome’s sRGB canvas: the eight sampled ratios range from 7.005 to 11.273. This sampled 8-bit calculation does not replace axe’s incomplete result or establish full WCAG compliance. No phone test is requested or performed. Server text is the local unpublished shell; no real construction claim, site photo, private register, model or control system enters the application.
