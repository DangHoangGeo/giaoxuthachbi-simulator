# Desktop timeline and freshness

Local implementation, 8 October 2026; unpublished actual inputs, no deployment. Use the [publishing runbook](progress-publishing.md) for reviewed content and the [evidence record](../../review/web-progress-2026-10-08/timeline/README.md) for exact checks. No phone work.

`/vi/progress` and `/en/progress` render an accessible server list, grouped by the known occurrence/end month or report month when occurrence is unknown. Newest is the default; chronological order and years actually present in the records are available. Equal dates sort by stable ID, not inferred work sequence. The page explains uncertainty and missing periods. It paginates 20 records without fetching photographs on the list. Detail routes use stable event IDs, show separate occurrence/report/first-publication/correction dates, evidence status, approved photographs when present, and visible withdrawal/correction notices. The language switch retains filters/page or event identity. No engineering completion percentage is shown.

The file-published release is fixed for a build. Known event IDs are generated from that release, with `dynamicParams=false`; unknown IDs return HTTP 404 before the shared loading boundary can stream a 200. A new event needs a new complete build. Public text, filters, pagination, language links and photograph anchors work without JavaScript. No-JavaScript readers can reload to check for updates.

The read-only `/api/public/version` responds with only state, release ID, checksum, release publication timestamp and latest event-update timestamp. It uses ETag conditional responses, explicit `no-store, max-age=0`, and generic 503 on invalid content; POST returns 405. It reads the same strict release as pages. There is no external content store or user-supplied filesystem path.

A visible online tab checks once and then every 60 seconds, with a 10-second request timeout. Hidden/offline states clear timers and abort requests; returning online/visible checks again. Failed checks retain the loaded content and last-success timestamp, with retries after 60/120/240/300 seconds (300-second cap). Successful checks reset backoff. The timestamp is separate from the polite status announcement. A changed checksum, including a rollback, offers an explicit reload; it does not replace the article or insert timeline rows automatically. Space is reserved for the notice/control to limit layout movement. Unmount removes listeners, timers and outstanding requests.

The browser tests use virtual time and intercepted synthetic version responses to verify the 60-second notice, failure retention and backoff. Visibility/network events are controlled in that test; actual desktop rendering and no-JavaScript reading are separately captured. This does **not** establish the two-minute origin-publication budget on an actual host: deployment propagation, cache behavior and intended parish network/device remain untested. Human collection/review and build time are separate and have no promised deadline. No “live” badge is displayed.

The temporary presentation app retains `fixtureOnly: true`, a conspicuous synthetic banner and synthetic captions. Only its temporary reader bypasses publication acceptance; production has no bypass. Its 45 records cover imprecise dates, unknown occurrence, pagination and a sanitized withdrawal. Both browser configurations use separate artifact directories; the final suites also ran sequentially. The earlier collision in a shared artifact directory and selector mistakes are retained in initial logs, not hidden. A real malformed-date error and missing-event soft-404 were fixed with their assertions retained.
